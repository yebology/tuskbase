# Backend Architecture

## Pattern: Clean Architecture (Use Cases + Services + DI)

```
Routes (HTTP) → Use Cases (business logic) → Services (external integrations)
                                            → Database (Prisma)
```

## Folder Structure

```
backend/src/
├── config/          # Environment validation (Zod), constants
├── types/           # Domain types (shared across layers)
├── services/        # Leaf services — each wraps one external dependency
│   ├── ai.service.ts           # OpenAI (intent, extraction, summarization, analysis)
│   ├── search.service.ts       # Tavily (web search, 20 sources)
│   ├── pdf.service.ts          # PDFKit (professional report generation)
│   ├── walrus.service.ts       # Walrus HTTP API (blob storage)
│   ├── memwal.service.ts       # MemWal SDK (AI memory)
│   ├── tatum.service.ts        # Sui transactions (via public RPC) + verification (via Tatum)
│   ├── tatum-mcp.service.ts    # Tatum MCP Data API (blockchain queries)
│   ├── provenance.service.ts   # Pure logic (hashing, trust scoring)
│   └── database.service.ts     # PostgreSQL via Prisma
├── usecases/        # Orchestration — combines multiple services
│   ├── research.usecase.ts     # Full deep research flow → PDF → on-chain
│   ├── verify.usecase.ts       # Report verification
│   └── recall.usecase.ts       # Semantic recall
├── routes/          # HTTP handlers — thin, just parse + delegate
│   ├── health.route.ts
│   ├── research.route.ts
│   └── memory.route.ts
├── container.ts     # DI container — wires everything
└── index.ts         # Entry point (Hono + @hono/node-server)
```

## Rules

1. **Services have no dependencies on each other** — they're leaf nodes
2. **Use cases depend on services** — they orchestrate
3. **Routes depend on use cases** — they're thin HTTP adapters
4. **Container creates everything** — single source of truth for wiring
5. **Types are shared** — imported by all layers
6. **Config is validated at startup** — app crashes fast if env is wrong

## Research Flow (main use case)

```
1. Tavily search (20 sources)
2. For each source (batches of 5):
   - OpenAI extractFacts (3-5 facts)
   - Walrus store snapshot
3. MemWal remember all facts (parallel)
4. OpenAI generate: summary, analysis, conclusion, chat summary (parallel)
5. PDFKit generate report (first pass — without provenance)
6. Compute SHA-256 hash of PDF
7. Walrus store PDF → get blob ID
8. Sui transaction (1 tx) → record hash + blob ID on-chain
9. PDFKit generate report (second pass — with provenance filled)
10. Walrus store final PDF
11. Return: chat summary + PDF download URL + provenance metadata
```

## Adding a New Feature

1. Need external integration? → Add a service in `services/`
2. Need business logic? → Add a use case in `usecases/`
3. Need HTTP endpoint? → Add a route in `routes/`
4. Wire it in `container.ts` and register route in `index.ts`

## Error Handling

- Services throw on failure
- Routes catch and return structured JSON errors
- Use cases handle non-critical failures gracefully (log + continue)
- Research continues even if individual sources fail (skip + log)

## Database

- Schema: `backend/prisma/schema.prisma`
- Models: Session, Message, Memory
- Migrations: `npx prisma migrate dev`
- Client: auto-generated by `npx prisma generate`

## Key Technical Decisions

| Decision | Why |
|----------|-----|
| Public Sui RPC for transactions | Tatum gateway doesn't support `suix_getLatestSuiSystemState` needed by SDK |
| Tatum RPC for reads/verification | Works fine for `sui_getTransactionBlock` and other read methods |
| Batch sources in groups of 5 | Avoid OpenAI rate limits |
| Two-pass PDF generation | Need hash before on-chain, but PDF needs provenance data filled |
| 1 Sui tx per report (not per-fact) | 20 sources × 5 facts = 100 txs would be too expensive/slow |
| Trust score in AI prompt | Let AI decide based on content + domain, not just domain heuristic |
